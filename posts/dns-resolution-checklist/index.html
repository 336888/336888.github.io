域名打不开，如何判断是 DNS 的问题

对比系统解析和指定解析器，再用 curl 验证 HTTPS。

先记下域名、错误信息和发生问题的网络。下面使用 example.com 作占位，排查时换成实际域名。

分别验证系统解析和指定 DNS

getent ahosts example.com
dig example.com A
dig example.com AAAA
dig @1.1.1.1 example.com A

getent 会走系统的名称解析配置，dig 发 DNS 查询，且能显示返回状态。查询超时表示未收到响应，NXDOMAIN 则是解析器返回的域名不存在。内网域名应对比单位指定的解析器，避免把内部名称发给公共 DNS。

用已知地址验证 HTTPS

curl -v --connect-timeout 5 --max-time 15 \
  --resolve example.com:443:192.0.2.10 https://example.com/

把示例 IP 换成确认属于该站点的地址。这条命令保留 HTTPS 的主机名和证书校验。若固定地址能通、正常请求失败，重点对比解析结果和请求选中的地址。若固定地址也失败，查看日志里失败的是连接、TLS 握手还是 HTTP 响应。浏览器开启安全 DNS 或设备配置代理时，也要确认测试和浏览器走的是同一条路径。
